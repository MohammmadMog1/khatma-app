# نختُم معاً — تنظيم ختمات القرآن

تطبيق ويب لتنظيم حجز أجزاء القرآن (30 جزءاً) ومتابعة الختمات.
**React + Vite + Tailwind CSS + Supabase**

## ما الذي يفعله؟

**المستخدم** (دخول برقم الهاتف فقط، والاسم أول مرة):
- يرى الختمات المفتوحة فقط، لكل ختمة رقم تسلسلي وشريط تقدّم.
- يحدّد أجزاءً متاحة ويحجزها دفعة واحدة، في أكثر من ختمة.
- عند عودته تظهر أجزاؤه في الأعلى: «أتممته» / «إلغاء الحجز» / «تراجع».
- فلتر: الكل / المتاحة / المحجوزة.
- عند تسجيل الدخول يكتب رقم الهاتف مرة واحدة؛ ويتأكد من الرقم مرتين عند إنشاء الحساب.
- صفحة «حسابي»: تعديل الاسم والرقم (تعديل الرقم يتطلب تأكيده أيضاً).
- تعرض الصفحة الرئيسية عدّادي الختمات الجارية والمنجزة.
- عند إتمام الأجزاء الثلاثين تظهر بطاقة دعاء ختم القرآن للمشاركين، ويستطيع المشرف إنهاء الختمة من أسفل الدعاء.
- شاشة افتتاحية بالشعار، ورحلة تعريفية تظهر أول مرة ويمكن إعادتها من زر «رحلة تعريفية».
- مسبحة إلكترونية تحفظ الذكر والعدد محلياً على الجهاز ولا تستخدم قاعدة البيانات.
- يمكن فتح المسبحة والرحلة التعريفية قبل تسجيل الدخول أيضاً.

**الأدمن** (هاتف + PIN من 6 أرقام):
- إنشاء ختمة جديدة (30 جزءاً تلقائياً).
- مراقبة الأجزاء: الحالة، اسم الحاجز، هاتفه، تاريخ الحجز، وسحب الحجز.
- تعديل اسم الختمة، وتفعيلها/إلغاء تفعيلها (يدوياً فقط)، وحذفها (لا يُسمح بحذف ختمة مفعّلة).
- قائمة المستخدمين، وتعديل اسم أي مستخدم ورقمه، وإضافة/إزالة أدمن.
- حذف حساب مستخدم نهائياً من لوحة الأدمن؛ تتحرر أجزاؤه المحجوزة، وتبقى الأجزاء المنجزة مكتملة دون ربطها بالحساب، وتحذف السجلات المرتبطة به.
- سجل تاريخي لكل حجز وإلغاء وإتمام وسحب.

## التشغيل

### 1) إعداد Supabase
1. أنشئ مشروعاً على [supabase.com](https://supabase.com).
2. افتح **SQL Editor** ونفّذ الملفات **بالترتيب**:
   1. `supabase/1-schema.sql`
   2. `supabase/2-functions.sql`
   3. `supabase/3-seed-admin.sql` ← **عدّل فيه اسمك ورقمك والـ PIN قبل التنفيذ**
   4. `supabase/4-v2-update.sql` (الإصدار 2: حذف/تعديل الختمات وتعديل الحساب)
   5. `supabase/5-home-stats.sql` (إحصاءات الختمات للواجهة الرئيسية)
   6. `supabase/6-admin-delete-user.sql` (حذف حساب مستخدم من لوحة الأدمن)

> إن كنت قد ثبّتّ المشروع سابقاً فنفّذ ملفات التحديث التي لم تنفّذها بعد، بما فيها السادس لتفعيل حذف الحسابات.
3. من **Project Settings ← API** انسخ `Project URL` و `anon public key`.

> صيغة الهاتف في قاعدة البيانات: رمز الدولة + الرقم بلا صفر.
> مثال: `0933123456` ← `963933123456` (غيّر `COUNTRY_CODE` في `src/lib/phone.js` لبلد آخر).

### 2) تشغيل الواجهة
```bash
cp .env.example .env      # ثم ضع القيمتين من Supabase
npm install
npm run dev
```
افتح الرابط الذي يظهر (عادةً http://localhost:5173).

### 3) النشر
`npm run build` ينتج مجلد `dist`. ارفعه على Vercel أو Netlify أو Cloudflare Pages،
وأضف المتغيرين `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY` في إعدادات الاستضافة.

## هيكل المشروع
```
supabase/            ملفات SQL (جداول + دوال + أول أدمن)
src/lib/             api (استدعاءات Supabase)، phone، constants
src/context/         AuthContext (حفظ الهوية في localStorage)
src/pages/           Login، KhatmaList، KhatmaView
src/pages/admin/     لوحة الأدمن (ختمات، مستخدمون، سجل)
```

## ملاحظات أمان
- الجداول محمية بـ RLS دون أي Policy، فلا يستطيع المتصفح الوصول لها مباشرة؛ كل شيء عبر دوال `security definer`.
- المستخدم العادي لا يرى هواتف الآخرين ولا هوياتهم، فقط `is_mine` لأجزائه.
- الأدمن: PIN مُشفّر (bcrypt)، قفل 15 دقيقة بعد 5 محاولات خاطئة، وجلسة تنتهي بعد 7 أيام.
- نقطة الضعف المقبولة: من يعرف رقم هاتف مستخدم عادي يستطيع الدخول بحسابه (هذا قرار التصميم).
